# Market Automation 交易规则

本文记录 `autoTrade_pm_refactored.py` 当前实际执行的交易条件，按“道—术”分层说明。阅读时先看原则和总流程，再按市场查看精确条件。

> 基线日期：2026-09-15。本文描述程序行为，不代表收益承诺，也不构成投资建议。代码修改交易事实时，应同步更新本文。

## 一眼看懂

| 项目 | AUTOBN | AUTOA |
| --- | --- | --- |
| 市场 | 币安 USDT 合约 | A 股 |
| 交易性质 | 真实市价单 | **虚拟成交，不连接券商** |
| 方向 | `BZ` 做多、`BD` 做空 | `BZ` / `N` 只做多 |
| 核心数据 | 30 根日 K、1h/5m OI、1h/5m 多空比、基差 | 前复权日 K、当日行情、成交量、涨停池、交易日历 |
| 扫描时间 | 每分钟调度，候选标的分 5 个分钟槽 | 工作日每分钟调度，仅 09:30（含）至 15:00（不含）有效 |
| 日报与标的刷新 | 08:00（北京时间） | 15:06（交易日） |
| 初始仓位 | 动态计算，默认 5 倍杠杆 | 每次固定虚拟买入 100 股 |
| 状态文件 | `alert_all.json` | `alert_all_A.json` |

主流程只有一条：

```text
标的池 -> 建立观察 -> 冷却/有效期检查 -> 方向扳机 -> 辅助数据确认
       -> 计算 ATR 轨道 -> 执行门槛 -> 开仓 -> 先检查退出 -> 再考虑加仓/移动轨道
```

最容易误读的五点：

1. `BZ`、`BD`、`N` 是程序标签，不是跨市场通用定义；同名标签必须结合市场理解。
2. AUTOBN 的飞书“信号”在账户、仓位、精度和健康度等下单准备检查通过后、真实订单提交前发送；收到信号不等于订单已经成交。
3. AUTOBN 多头在首次部分止盈前，字段中的价格止损不会触发；此阶段主要使用 OI 止损。空头价格止损从开仓后即生效。
4. 两个策略的 DCA 都没有代码层面的次数上限。
5. AUTOA 全部成交均为本地模拟；信号、持仓和盈亏记录不能当作券商成交回报。

## 道：交易与执行原则

### 1. 先观察，再扣扳机

程序不把一次异常直接等同于开仓：

- AUTOBN 先用价格、成交量和 OI 建立 `BZ` 或 `BD` 观察，之后再等待方向与 OI/多空比确认。
- AUTOA 先由每日涨停池建立候选，之后再等待放量跳空的 `BZ`，或已有 `BZ` 之后的 `N` 形态。
- 观察有有效期；平仓后的重开还受冷却期限制。

### 2. 价格给方向，参与度做确认

- 价格相对前一日收盘的变化决定 AUTOBN 是检查多头还是空头。
- 成交量、持仓量 OI 和多空账户比例用于判断这次价格变化是否达到策略要求。
- 基差只追加 `Basis` 标签，不决定能否开仓。

### 3. 用波动尺度定轨道

两个市场都用 ATR 表达波动，而不是写死固定价差：

- 常规初始止盈轨道距离为 `3 * ATR`。
- AUTOBN 与 AUTOA `BZ` 的常规初始止损轨道距离为 `1 * ATR`；AUTOA `N` 改用 `BZ` 观察以来的最低价。
- ATR 最多取当前 `HL2` 的 10%，避免极端历史波动把当前轨道拉得过远。
- 加仓后，止盈目标按 `ATR * 0.5^DCA次数` 收紧。

这些规则只定义程序中的触发价，不保证真实成交价；AUTOBN 市价单仍有滑点风险。

### 4. 先退出，再加仓

每次管理已有持仓时，顺序固定为：

```text
止损/止盈/OI或成交量退出 -> 风控数据恢复 -> DCA -> 更新止盈止损轨道
```

同一轮同时满足退出和加仓时，退出优先。数据缺失或状态冲突时，程序倾向于跳过新开仓或加仓，而不是把未知状态当作安全状态。

### 5. 信号、订单、成交是三件事

| 层次 | 含义 |
| --- | --- |
| 策略条件 | 行情与指标满足规则，生成交易意图 |
| 下单准备 | 检查真实持仓、余额、精度、名义价值、杠杆和账户健康度 |
| 成交确认 | 交易所明确返回成交，或通过订单查询确认成交 |

AUTOBN 只有确认成交后才更新正式持仓和写入平仓记录。订单结果未知时会保留待确认订单，后续只查询原订单，不重复提交。

当前 AUTOBN 的飞书信号实际属于“已具备下单条件的执行前通知”，不是只由行情和冷却期决定的纯分析信号：余额、持仓、精度、名义价值或健康度检查失败时，不会发送该信号。若产品上要把它定义为纯分析信号，需要另行调整代码时点。

### 6. 状态以可恢复为先

- AUTOBN 提交真实订单前先持久化订单标识；中断后优先核对原订单。
- 交易所已有仓位但本地没有对应策略记录时，不允许重复开仓，而是进入 `N` 恢复流程。
- 通知失败不回滚已经确认的成交，也不改变交易状态。

## 术：共同计算口径

### 1. K 线记号

| 记号 | 含义 |
| --- | --- |
| `D0` | 当前正在形成的日 K |
| `D-1` | 最近一根已完成日 K |
| `O/H/L/C/V` | 开盘价、最高价、最低价、收盘价、成交量 |
| `HL2` | `(H + L) / 2` |
| 当前价 | 当前日 K 的 `C`，不是下单时的标记价格 |

AUTOBN 的日 K 和历史 OI 以 UTC 周期边界取数；调度、日报和状态日期使用 `Asia/Shanghai`。

### 2. ATR

单根真实波幅：

```text
TR = max(H - L, abs(H - 前收盘), abs(L - 前收盘))
ATR最终值 = min(策略ATR, D0.HL2 * 10%)
```

| 市场 | 实际算法 |
| --- | --- |
| AUTOBN | 30 根日 K 产生 29 个 TR；前 7 个取均值，之后使用 7 周期 Wilder RMA |
| AUTOA | 最近 5 个 TR 的简单平均 |

### 3. 切比雪夫异常上界

程序对样本使用样本标准差（`ddof=1`），以 `k = abs(x - mean) / std` 计算上界：

```text
k <= 1 时，上界 = 1
k > 1 时，上界 = 1 / k^2
样本标准差为 0 时，当前实现返回 0
```

文中的“上界小于 1% / 5%”均为严格 `<`，等于阈值不通过。

### 4. 标签

| 标签 | AUTOBN | AUTOA |
| --- | --- | --- |
| `BZ` | 放量上涨观察及做多链路 | 放量、跳空、阳线形态及做多链路 |
| `BD` | 高位量价/OI观察及做空链路 | 不使用 |
| `N` | 交易所实仓缺少本地记录时的恢复标签 | 已有 `BZ` 观察后的再次跳空做多形态 |
| `Basis` | 基差绝对方向超过 2% 时追加的记录标签，不是开仓门槛 | 不使用 |
| `DCA` | 每次成功加仓追加一次 | 每次虚拟加仓追加一次 |

重复标签会写成 `DCA*2`、`DCA*3` 等展示形式。

## 术一：AUTOBN 币安合约

### 1. 扫描范围与数据前提

- 标的池为币安状态是 `TRADING`、计价资产严格等于 `USDT` 的交易对。
- 当前日 K 来自 WebSocket，必须是当前 UTC 日尚未收盘的 `1d` K 线；再拼接 29 根连续、完整的历史日 K。
- 普通候选按排序结果分为 5 个槽，每个 5 分钟窗口各处理一次；已有持仓和待确认订单每分钟都处理。
- 单轮扫描最长 55 秒，并发交易/历史请求上限为 8。
- 缺少 29 根历史日 K、行情过期、数据结构异常或当前批次未收到有效 WebSocket 行情时，本轮不分析该标的。

### 2. 建立观察

#### BZ 做多观察

以下条件必须同时满足：

1. `D0.C > D-1.C`。
2. `D0.V >= 最近10根日K成交量最大值`，最近 10 根包含 `D0`。

满足后写入 `BZ` 观察。观察有效期为 24 小时。

#### BD 做空观察

初次建立 `BD` 观察时，以下条件必须同时满足：

1. `D0.C >= 前29根日K收盘价最大值`，即当前价格位于这 30 根 K 的收盘高位。
2. 最近 3 根日 K 的成交量最大值严格小于 30 根日 K 的全局成交量峰值。
3. 该全局成交量峰值位于“最近 10 根剔除最近 3 根”的 7 根区间内，即 `D-9` 至 `D-3`。
4. 能取得 30 个完整 `1d` OI 点和当前 `5m` OI，并拼成实时 OI 窗口。
5. 当前 `5m` OI 严格大于该窗口倒数第 10 至倒数第 4 个点的 OI 峰值。
6. 上述旧 OI 峰值相对更早 OI 样本的切比雪夫上界 `< 5%`。

满足后写入 `BD` 观察。观察有效期为 7 天。

已有 `BD` 观察的维护规则：

- 若 `D0.V >= 前29根日K成交量峰值`，先删除旧 `BD` 观察。
- 若价格仍在 30 根收盘高位、最近 3 根没有出现全局量峰，且当前 OI 仍高于旧 OI 峰，则刷新观察价格与时间。
- 刷新时不再要求“量峰必须位于 D-9 至 D-3”，也不重新要求 5% 的初次异常门槛。
- 同一轮同时能建立 `BZ` 和 `BD` 时，`BZ` 优先。

### 3. 从观察到开仓

#### BZ 开多扳机

先满足方向条件：

```text
D0.C > D-1.C，并且当前观察包含 BZ
```

再同时通过下列确认：

1. 取得 30 个 `1h` 多空账户比、当前 `5m` 多空账户比、30 个 `1h` OI 和当前 `5m` OI。
2. 从 30 个 `1h` OI 中剔除最近 6 个，以前 24 个作为异常样本。
3. 当前 `5m` OI `>=` 全部 30 个 `1h` OI 的最大值。
4. 当前 `5m` OI 相对前 24 个 OI 样本的切比雪夫上界 `< 1%`。
5. OI 样本末点与 `1h` 多空比必须能按时间戳对齐。
6. 下面的融合多仓占比不得小于当前 `5m` 多仓占比：

```text
O0 = 剔除最近6小时后，样本末点的 OI
L0 = 与 O0 同时刻的多仓账户占比
Onow = 当前5m OI
Lnow = 当前5m多仓账户占比

融合占比 = (O0 * L0 + (Onow - O0) * 0.4) / Onow
要求：融合占比 >= Lnow
```

多仓账户占比优先读取接口的 `longAccount`；缺失时按 `longShortRatio / (1 + longShortRatio)` 换算。

开多时保存的 OI 止损阈值为：

```text
max(当前5m OI * 90%, OI样本均值 + 10 * OI样本标准差)
```

#### BD 开空扳机

以下条件必须同时满足：

1. `D0.C < D-1.C`。
2. 当前观察包含 `BD`。
3. 当前 `5m` OI `<= 30个完整1d OI的最大值 * 90%`。

BD 开空不使用多空账户比，也不保存 OI 止损阈值。

#### ATR 轨道与 Basis 标签

通过方向确认后，以 `D0.HL2` 为中心计算：

| 方向 | 初始止盈 | 初始止损 |
| --- | --- | --- |
| 多头 | `HL2 + 3 * ATR` | `HL2 - 1 * ATR` |
| 空头 | `HL2 - 3 * ATR` | `HL2 + 1 * ATR` |

ATR 必须为有限正数，否则不开仓。

基差率计算为 `(标记价格 - 指数价格) / 指数价格`：

- 多头基差 `< -2%` 时追加 `Basis`。
- 空头基差 `> 2%` 时追加 `Basis`。
- 未达到阈值仍可开仓；接口失败按 0 处理，因此也不会阻止开仓。

### 4. 真实下单门槛与仓位

策略条件通过后，还要通过执行层。任一项失败都不会提交订单：

1. 交易对数量精度、止盈价和止损价有效。
2. 新开仓时，交易所账户中该标的不能已经存在任何方向的仓位。
3. 可用余额大于 0，且能取得有效标记价格。
4. 标记价格到止损、止盈的距离都大于 0。
5. 向下取整到交易对数量精度后，名义价值至少为 10 USDT。
6. `名义价值 / 5倍杠杆 <= 可用余额`。
7. 账户健康度至少为 70。

原始数量按止损距离与止盈距离共同计算：

```text
止损数量 = 账户权益 * 10% / abs(标记价格 - 止损价)
止盈数量 = 账户权益 * 10% / abs(止盈价 - 标记价格)
原始数量 = (止损数量 + 止盈数量) / 2

数量上限 = 可用余额 * 10% / 标记价格
最终数量 = min(原始数量, 数量上限)，再按精度向下取整
```

这里的 10% 是程序的计算参数，不是“最大亏损必定不超过账户 10%”的保证。市价成交、跳空、滑点和公式取平均都会使真实结果不同。

健康度口径：

```text
health = round((1 - 维护保证金 / 账户权益) * 100)
```

结果限制在 0 至 100。账户未返回维护保证金时，程序用“新仓名义价值的 0.4%”补充估算；低于 70 拒绝下单。通过后先把该交易对杠杆设为 5 倍，再提交带 `positionSide` 的市价单。

AUTOBN 同时存在三种价格口径：

- 策略触发价是当前日 K 收盘价 `D0.C`。
- 仓位计算和开仓通知中的委托价是下单准备时取得的标记价格。
- 新仓写入本地状态时，初始 `entry_price` 仍是策略触发价；启动/每日账户核对或成功 DCA 后，才可能由交易所 `entryPrice` 修正。

因此，在本地均价被修正前，止盈、止损和 DCA 判断使用的是本地 `entry_price`，不一定等于真实开仓成交均价。

### 5. AUTOBN 持仓管理

#### 退出优先级

每轮按以下顺序检查，命中一项就不再执行后续规则：

1. **价格止损**
   - 多头：仅当至少完成过一次部分止盈（`tp_count > 0`）后，`价格 <= 止损价` 才全平，原因为“止盈后价格止损”。
   - 空头：`价格 >= 止损价` 即全平；尚无移动止损原因时记为“初始止损”。
2. **止盈**
   - 首次止盈或后续止盈均计划平掉 70% 当前仓位。
3. **OI 止损**
   - 仅多头使用；当前 `5m` OI `<=` 开仓时保存的 OI 阈值时全平。

若计划平掉 70% 的名义价值不足 10 USDT，执行层会改为全平。部分平仓数量按交易对精度向下取整；无法得到有效数量时，本轮暂缓。

#### 首次止盈

首次止盈距离为：

```text
min(
  当前止盈价与持仓均价距离 / 3,
  max(min(当前ATR, 开仓均价 * 5%), 1e-8)
)
```

- 多头盈利达到该距离时触发；若价格直接越过完整止盈位也触发。
- 空头使用方向相反的同一距离。
- 成功部分平仓后 `tp_count + 1`。
- 多头下一止盈先设为 `平仓价 + min(ATR, 平仓价 * 5%)`。
- 空头下一止盈先设为 `平仓价 - min(ATR, 平仓价 * 5%)`，并把止损收紧到至少保护已有盈利的 70%。

#### 后续止盈

价格再次到达当前止盈位时，再计划平掉剩余仓位的 70%。成功后按当前价格和 ATR 重建下一段 `3 * ATR` 止盈轨道；空头同时重建价格止损轨道。

#### DCA 加仓

退出条件均未命中后才检查：

| 方向 | 加仓条件 |
| --- | --- |
| 多头 | `当前价 < 当前持仓均价 - ATR` |
| 空头 | `当前价 > 当前持仓均价 + ATR` |

每次加仓仍要重新通过余额、健康度、最小名义价值和动态数量检查。成交后重新查询交易所均价，追加一个 `DCA` 标签，并收紧止盈：

```text
多头候选止盈 = 新均价 + ATR * 0.5^DCA次数
空头候选止盈 = 新均价 - ATR * 0.5^DCA次数
```

新止盈不会比原止盈更远。**当前实现没有 DCA 次数、总仓位或累计风险的独立上限；每次只受当次执行门槛约束。**

#### 动态轨道

未退出、未加仓时，每次成功管理都会把止盈向均价方向收紧：

- 每轮衰减量为 `当前止盈距离 * 0.01% * (1 + tp_count)`。
- 同时受当前 `HL2 +/- 3*ATR` 轨道约束。
- 有 DCA 时，再受 `ATR * 0.5^DCA次数` 目标约束。
- 多头止盈不得低于均价；空头止盈不得高于均价。

空头止损只向盈利方向移动：

- 尚未达到首次止盈距离时，使用当前 `HL2 + ATR` 轨道。
- 达到首次止盈距离或已经部分止盈后，止损设为保护当前浮盈的 70%，允许约 30% 浮盈回撤。
- 新止损只会比旧止损更低，不会放宽。

多头不做上述移动价格止损；首次止盈前只检查 OI 止损，首次止盈后才启用保存的价格止损。

### 6. 平仓后的观察与冷却

- `BD` 空头全部平仓后删除观察，可由后续行情重新建立。
- `BZ` 多头全部平仓后保留观察，并设置 24 小时禁止重开。
- 同方向观察重建或刷新时，继承尚未结束的禁止重开时间。
- `BZ` 与 `BD` 互相覆盖时不继承原观察的禁止重开时间；已有 `BD` 因 `D0.V >= 前29根日K成交量峰值` 被删除后，同一轮建立的 `BZ` 同样不继承。
- 冷却检查发生在行情请求之前；冷却中不做开仓分析。

### 7. 交易所仓位恢复

每日刷新或首次启动核对账户时：

- 本地有仓位、交易所无对应方向仓位：删除本地仓位。
- 交易所有仓位、本地没有或方向不一致：进入恢复队列，禁止重复开仓。
- 只有同一标的恰好存在一个可识别的 `LONG` 或 `SHORT` 仓位时才能恢复。
- 恢复仓位统一标记为 `N`，使用当前均价和当前 ATR 重建轨道；历史 DCA 次数和止盈次数不会猜测回填。
- 恢复多头还必须重建 OI 阈值；失败时保持恢复状态并禁止新开仓。

这里的 AUTOBN `N` 只表示状态恢复，不是新的行情入场策略。

## 术二：AUTOA A 股

### 1. 标的池与运行边界

- 每个交易日 15:06 从东方财富当日涨停池加入或刷新观察标的。
- 历史与当日行情来自腾讯前复权日 K；交易日历来自新浪。
- 盘中只在 09:30（含）至 15:00（不含）处理。
- 新观察当天不允许开仓；正常情况下 15:06 建池，最早下一个交易日分析。
- 观察 30 天未刷新则过期。旧观察未再次进入涨停池时不会在日报刷新阶段立刻删除，而是等待超时。
- 行情时间最多允许落后预期时间 5 分钟；午休期间以 11:30 快照作为有效基准。
- 交易日历暂不可用时只管理已有持仓的退出，不建立新仓、不加仓、不更新动态轨道。

### 2. BZ 做多条件

只有已在观察池中的股票才检查 `BZ`。以下条件必须同时满足：

1. 至少有 20 根日 K。
2. `D0.C > D0.O`，当天为阳线。
3. `D0.O > D-1.H`，当天向上跳空高开。
4. `D0.V >= 最近5根日K成交量最大值`，最近 5 根包含 `D0`。
5. 以 `D-19` 至 `D-5` 共 15 根成交量为样本，`D0.V` 的切比雪夫上界 `< 1%`。

触发后：

- 观察标签加入 `BZ`。
- `bz_reference_high` 记录 `D-1.H`。
- 观察止损参考价改为 `D0.L`。
- 后续只要观察仍含 `BZ`，参考价持续更新为“原参考价与当前日最低价的较小值”。

若本轮触发 `BZ` 且 ATR 有效，会直接生成 `BZ` 开多意图。

### 3. N 做多条件

`N` 不是独立入池信号，必须建立在已有 `BZ` 观察上。以下条件必须同时满足：

1. 本轮没有再次触发 `BZ`。
2. 观察中已有 `BZ`，且 `bz_reference_high` 为有效正数。
3. `D0.C > D0.O`。
4. `D-1.L < bz_reference_high`。
5. `D0.O > D-1.H`。

满足后向观察追加 `N`，并生成做多意图。`N` 的初始止损使用从 `BZ` 观察以来累计的最低价；它不使用成交量止损，也不移动价格止损。

### 4. AUTOA 开仓与初始轨道

| 类型 | 初始止盈 | 初始止损 | 成交量保护值 |
| --- | --- | --- | --- |
| `BZ` | `D0.HL2 + 3*ATR` | `D0.HL2 - ATR` | `D-19` 至 `D-5` 的平均成交量 |
| `BZ,N` | `D0.HL2 + 3*ATR` | `BZ` 观察以来最低价 | 同样记录，但 N 持仓不使用它触发退出 |

ATR 必须为有限正数。AUTOA 执行层随后立即按当前价**虚拟成交 100 股**，没有余额、涨跌停可成交性、手续费、滑点、券商持仓或资金检查。

### 5. AUTOA 持仓管理

开仓当日完全不管理该持仓；从后续日期开始，按以下顺序处理。

#### 全量退出

1. `当前价 >= 止盈价`：全平，原因为“止盈”。
2. `当前价 <= 止损价`：全平，使用已有移动止损原因，否则记为“初始止损”。
3. 非 `N` 持仓若 `0 < D-1.V <= 开仓时保存的15根样本平均量`：全平，原因为“成交量止损”。
4. 若尚未命中以上条件，但盈利达到首次止盈距离：全平，原因为“首次止盈”。

AUTOA 的“首次止盈”不是部分平仓，而是一次性虚拟全平。其距离公式与 AUTOBN 相同：

```text
min(
  当前止盈价与持仓均价距离 / 3,
  max(min(当前ATR, 持仓均价 * 5%), 1e-8)
)
```

#### DCA 加仓

退出条件未命中，且不是只退出模式时：

```text
当前ATR > 0
当前持仓均价 > 0
当前价 < 当前持仓均价 - ATR
```

满足后虚拟加仓 100 股，按累计股数重算均价，追加一个 `DCA` 标签，并把止盈收紧为不高于：

```text
新均价 + ATR * 0.5^DCA次数
```

当前实现没有 DCA 次数上限。

#### 动态轨道

未退出、未加仓时：

- 止盈每轮按当前“止盈价 - 均价”距离衰减 0.1%。
- 同时不得高于当前 `D0.HL2 + 3*ATR`。
- 有 DCA 时，还不得高于 `均价 + ATR * 0.5^DCA次数`。
- 最终止盈不得低于持仓均价。
- 非 `N` 的止损取 `max(旧止损, D0.HL2 - ATR)`，只上移不下移。
- `N` 的止损不随 ATR 轨道移动。

### 6. AUTOA 平仓冷却

全部平仓后保留观察，但先记录平仓日期，等交易日历可用时再计算可重开时间：

```text
平仓后的第1个交易日：仍禁止重开
平仓后的第2个交易日 00:00 起：允许重新开仓
```

因此它不是简单的 24 或 48 小时冷却，而是“跳过一个完整后续交易日”。

## 条件未触发时如何判断

没有信号通常不是单一原因。按以下顺序排查最接近程序实际执行顺序：

1. 是否已有待确认订单、真实仓位冲突或恢复中的仓位。
2. 观察是否存在，是否仍在冷却期，是否已经超时。
3. 当前行情是否有效、连续、足量且未过期。
4. 当前价格方向是否与观察标签匹配。
5. 成交量、OI、多空比和切比雪夫条件是否全部通过。
6. ATR、止盈价、止损价是否为有限正数。
7. AUTOBN 的余额、精度、最小名义价值、杠杆和健康度是否通过。
8. 查看运行日志中的“跳过”“恢复”“待确认”“数据不足”和请求诊断信息。

条件比较中的 `>`、`>=`、`<`、`<=` 均按本文原样执行；临界值相等时是否通过，取决于具体符号，不能互换。
